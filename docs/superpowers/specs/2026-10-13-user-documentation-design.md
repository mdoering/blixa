# User documentation — design

**Date:** 2026-10-13 · **Status:** implemented (showcase project on blixa.dev pending)

## Goal

Blixa has ~45 user-facing features but no end-user documentation — only four `InfoLabel` popovers
and a few dimmed hints in project Settings. New users of blixa.dev.catalogueoflife.org need a guide
to what the editor can do, how its core concepts work, worked examples for typical tasks, and a
realistic dataset to practise on.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Format & hosting | **In-app `/help`**: markdown pages in `frontend/src/help/pages/`, rendered with the already-present `react-markdown` (+ `remark-gfm`) | Same pattern as ChecklistBank's `/about/:mdFile`; versioned and deployed with the code (push to `main` → Jenkins); no extra build or hosting; enables contextual `?` links from each screen |
| Access | `/help` is public (under `PublicLayout`), readable before sign-in | Prospective users need it to decide whether to apply for access |
| Structure | Diátaxis-style: Getting started (overview, access, concepts, tour, tutorial) · How-to guides (one per workflow area) · Reference (TextTree, import formats, validation rules, glossary, FAQ) | Separates learning, doing and looking up |
| Playground data | A curated **Felidae** ColDP (from COL via ChecklistBank, CC BY) with deliberate flaws for the tutorial, committed unzipped under `demo/felidae/` and zipped to `frontend/public/help/demo/blixa-playground-felidae.zip` | Familiar group, small, rich synonymy; flaws give the tutorial something real to fix |
| Sandbox | "Try it with demo data" on the Projects page imports the bundled zip into a private project. A public showcase copy (`/p/playground`) on blixa.dev stays owner-edited. | Everyone gets an isolated sandbox; no shared state to reset; no scripted ORCID login needed |
| Screenshots | Generated by a Playwright script (`npm run screenshots`) against the local dev stack, written to `frontend/public/help/img/` | Reproducible after UI changes instead of going stale |

## Help system

- `src/help/toc.ts` — ordered sections → pages (slug, title); drives sidebar and prev/next.
- `src/help/pages/*.md` — loaded lazily with `import.meta.glob(..., { query: '?raw' })`.
- `src/help/HelpPage.tsx` — `/help` and `/help/:page`; sidebar | markdown | on-page contents.
  Headings get slug ids + anchors; internal links route via react-router; unknown slug → `/help`.
- `src/components/HelpLink.tsx` — `?` icon opening a help page/section in a new tab; in both app
  headers and on each main screen / major modal.

## Out of scope

Full-text search over help; a portal link from `catalogueoflife.org/tools/editing` (portal repo);
a shared, editable sandbox with periodic reset.
